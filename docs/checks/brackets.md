# Проверка сеток и правил турнира (для финального этапа)

Выполнять только на **копии** демо-БД: отдельный кластер через `FS_DEMO_DIR` / `FS_DEMO_PGPORT` / `FS_DEMO_ENV` (см. README) или копия базы `fightscore_demo`. Рабочую демо-базу не трогать.

## 0. Миграция

1. Применить `0005_brackets.sql` к копии (`npm run db:migrate` с переменными копии).
2. Убедиться, что старые поединки не изменились: `SELECT count(*) FROM matches WHERE bracket_id IS NOT NULL` → `0`.
3. Повторный запуск миграций ничего не делает (контрольная сумма совпадает).

## 1. Unit

- `npx vitest run src/modules/matches/bracket.spec.ts` — раскладки 2/3/5/8, посев, проходы без боя, направление победителя.

## 2. Создание сетки (`POST /api/tournaments/:id/brackets`)

| Участников | Ожидается |
|---|---|
| 2 | размер 2, один поединок (финал) |
| 3 | размер 4: 1 поединок 1-го круга, финал с 1-м номером на красном углу |
| 5 | размер 8: 1 поединок 1-го круга (4–5), во 2-м круге 1-й номер ждёт, 2-й и 3-й уже стоят в одной паре |
| 8 | размер 8, 4 + 2 + 1 поединок, без проходов |

- Повторно для той же дисциплины → `409 Сетка для этой дисциплины уже создана`.
- Незарегистрированный участник или чужой `entryId` → `400`.
- Турнир «Завершён» → `409`; в архиве → `409`.
- Ошибка посередине (например, недоступная версия правил) — в БД нет ни сетки, ни её поединков (одна транзакция).
- `PUT /api/matches/:id/setup` для поединка сетки → `409`; на странице поединка формы состава нет, есть пояснение и ссылка на сетку.

## 3. Продвижение

- Провести поединок 1-го круга до подтверждения: победитель появился в следующем поединке на нужном углу (чётная позиция — красный), `bracket_advanced_side` выставлен.
- Подтвердить финал: на вкладке «Сетка» плашка «Победитель сетки».
- Ничья или окончание без победителя: продвижения нет, на карточке кнопки выбора прохода.
- Обычный поединок вне сетки: подтверждение работает как раньше, `bracket_advanced_side` остаётся `NULL`.

## 4. Отмена и ручной проход (`POST /api/matches/:id/walkover`)

- Отменённый поединок сетки → выбрать угол → спортсмен в следующем поединке, запись `bracket.walkover` в журнале.
- Повторный вызов → `409 Проход из этого поединка уже определён`.
- Поединок с подтверждённым победителем → `422 INVALID_TRANSITION`.
- Следующий поединок уже начат → `422`.
- Пустой угол → `400`.

## 5. Целостность в БД (на копии, вручную)

```sql
-- позиция занята дважды
INSERT INTO matches (...) VALUES (... same bracket_id, round, slot ...);       -- ожидается unique_violation
-- поединок в сетке чужого турнира
UPDATE matches SET bracket_id = '<bracket другого турнира>', bracket_round = 9, bracket_slot = 0 WHERE id = '<id>'; -- foreign_key_violation
-- проход у обычного поединка
UPDATE matches SET bracket_advanced_side = 'red' WHERE bracket_id IS NULL AND id = '<id>'; -- check_violation
```

## 6. Конкурентность

- Одновременно «В архив» и «Начать поединок» в этом турнире: проходит только одно; при победе архива судья получает конфликт версии, после обновления — «Турнир в архиве».
- Архивация при поединке «Идёт» / «Ждёт подтверждения» → `409` с числом активных поединков.
- В логах PostgreSQL нет `deadlock detected`.

## 7. Жизненный цикл (добавлено)

- Подтвердить поединок 1-го круга, держа открытыми судейскую панель и табло следующего поединка: новый участник появляется без перезагрузки. Вкладка «Сетка» обновляется в течение ~10 с.
- То же после ручного прохода.
- Отменить поединок сетки с одним известным участником → `409`, кнопки «Отменить» на странице поединка нет.
- Отменить пару с двумя участниками → затем ручной проход → участник в следующем поединке.
- Одновременно: «Создать сетку» и «Завершить турнир» / «В архив» — сетка либо создаётся до смены статуса, либо получает `409`.
- Табло получает только публичную проекцию (`display.match`), без внутренних полей.
