# Проверка судейства (для финального этапа)

На копии демо-БД, с двумя устройствами: планшет судьи (касания) и ТВ-табло.

## Поток поединка
- «Готов к старту» → «Начать поединок» → индикатор «Идёт», таймер считает.
- «Пауза» → индикатор «Пауза»; «Старт» → снова «Идёт». Время вышло → «Время вышло», кнопка «Старт» недоступна.
- Начисление и снятие очков, нарушения (с подтверждением), исправление события из журнала.
- «Завершить поединок» → «Ждёт подтверждения» → «Подтвердить» главным судьёй → «Завершён», в панели победитель, способ, счёт; для сетки — строка о переходе в следующий круг.

## Защита от повторов
- Двойное быстрое касание «+1» на планшете → одно начисление.
- Два касания подряд с паузой > 0,4 с → два начисления (обычная работа).
- Быстрое двойное касание «Пауза»/«Старт» → одна команда, кнопка показывает загрузку, ложной ошибки нет.
- Потеря ответа без разрыва (замедлить сервер) → команда повторяется сама с тем же id, счёт не удваивается (`duplicate`).

## Соединение
- Выключить сеть на планшете: баннер «Связь с сервером потеряна», ввод заблокирован; включить — данные и таймер актуальны, неотправленные команды ушли один раз.
- Перезагрузить страницу во время идущего таймера: время совпадает с табло (± доля секунды).
- Перезапустить backend во время паузы: панель и табло переподключаются, состояние то же.

## Права
- Судья без права `confirm` не видит рабочей кнопки подтверждения; прямой вызов команды → отказ сервера.
- Не назначенный пользователь → «только просмотр».

## Табло и сетка
- После подтверждения табло показывает «Победа: … · способ» без внутренних полей (журнал, судьи, id пользователей).
- В сетке победитель появляется в следующем поединке; судейская панель и табло следующего поединка обновляются без перезагрузки.
